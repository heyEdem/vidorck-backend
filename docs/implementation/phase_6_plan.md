## Verified facts that shape the design

- No real workbook exists, so the importer defines its own header contract ([catalogue-import.md](../catalogue-import.md)). A workbook with missing, extra or differing headers stops before any snapshot or write, printing expected vs found and a proposed mapping.
- `product_variants.product_code` and `bundles.product_code` are required and unique; `products.normalized_name` is indexed but not unique, so more than one match is an ambiguity error.
- Variant price = `source_price_minor + 200` (mirrors `ManageCatalog::variantFields`); bundle price is the fixed workbook price with no markup.
- `AuditLogger::record(null, …)` records a SYSTEM actor; `media.uploaded_by` is nullable.
- `HandleChargeSuccess`/`CreateOrderFromAttempt` only refuse `SUCCEEDED`, so a late webhook on an `ABANDONED` attempt still creates the order. Expiry is safe.
- Only `orders.checkout_attempt_id` and `checkout_attempts.parent_attempt_id` reference attempts (restrict on delete).
- Media is retired via `retired_at`; there is no media DELETE trigger.
- Phase 5 review defers failed-job pruning (encrypted contact payloads) to 6.4.
- PHP has `zip`, `xml`, `gd`; `phpoffice/phpspreadsheet` is not yet installed.

## Design

- **Command:** `catalog:import {file} --dry-run|--apply [--images=dir] [--report=path.csv]`; exactly one mode required. Validation runs first in both modes; dry-run makes no DB, media, audit or queue writes.
- **No service extraction.** The importer writes models directly inside per-product transactions. Admin actions stay untouched.
- **Matching:** product by `CatalogNormalizer::normalize(name)`, variant by normalised size. Products with conflicting product-level values across rows are rejected as a group; a bad variant row skips only that row.
- **Unchanged detection:** compare typed product fields, hair-type ID set, and variant label/code/source price/price/active/order; bundles compare scalars plus sorted `(variant_id, quantity, display_order)` tuples. Slug, image alt and image position of existing products are preserved.
- **Missing image** is an error only when `--images` is given; without it images are not checked. With `--images`, a product that already has active media reports image `unchanged` (replacement remains an admin task); two plausible files are an error row.
- **Snapshot:** `VACUUM INTO storage/backups/catalog-{timestamp}.sqlite` before the first write, outside any transaction, behind a small `CatalogSnapshot` seam; failure aborts the run.
- **Finalisation:** after an apply, one transaction appends one SYSTEM `catalog.import.applied` audit row (counts) and dispatches one `RevalidateStorefront` (database queue, so atomic). A crashed run leaves no audit row until re-run; recovery is the snapshot plus an idempotent re-run.
- **Scheduler:** compare-and-set updates, bounded chunks, `withoutOverlapping()`.

### Scheduled jobs

| Job | Frequency | Rule |
|---|---|---|
| Expire attempts | hourly | `PENDING`, `expires_at <= now`, `verified_at` null, no order → `ABANDONED` (CAS on status) |
| Re-verify attempts | every 15 min | `PENDING`, created ≥15 min ago, `scheduled_verified_at` null, no order: set marker, then run `CheckCheckoutStatus` once |
| Media cleanup | daily | `retired_at` > 30 days ago: delete files, then row |
| Session prune | daily | database driver only: `last_activity` older than `session.lifetime` |
| Failed attempt cleanup | daily | `FAILED`, created > 90 days ago, no order, no child attempt |
| Failed-job prune | daily | `queue:prune-failed --hours=24` |
| SQLite optimise | daily | `PRAGMA optimize` |
| Litestream freshness | hourly | Placeholder command that reports "not configured" (Phase 7.4 wires it) |
